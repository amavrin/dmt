# TODO: подготовка репозитория к агентской разработке

Этот файл — ваш учебный маршрут. Его цель не сделать работу за вас, а помочь превратить репозиторий в среду, где AI-агент сможет работать предсказуемо, маленькими проверяемыми шагами.

Как пользоваться этим планом:
- двигайтесь по порядку;
- не переходите к следующему шагу, пока не появился ожидаемый артефакт;
- после каждого шага сверяйтесь с признаком готовности;
- если формулировка задачи для агента получается слишком широкой, сначала упростите её до одного результата и одного способа проверки.

### [ ] 2. Выделить термины предметной области
**Цель:**
Подготовить общий словарь для вас и агента. Агент часто ошибается не в синтаксисе, а в смыслах: если термины не зафиксированы, он начинает додумывать.

**Что сделать:**
- выписать ключевые сущности проекта;
- отделить сущности предметной области от UI-элементов;
- для каждого термина кратко определить смысл в контексте проекта.

**Подсказка по типам терминов:**
- доменные: автомобиль, поза автомобиля, угол руля, траектория, препятствие, коллизия;
- вычислительные: шаг симуляции, прогноз траектории, центр поворота;
- UI-термины: сцена, слой визуализации, инструмент редактирования.

**Ожидаемый артефакт:**
Отдельный glossary-раздел или отдельный markdown-файл со списком терминов и краткими определениями.

**Признак готовности:**
Для каждого важного слова в проекте у вас есть одно устойчивое значение, и два разных читателя не должны понимать его по-разному.

## Мини-чеклист качества перед каждой задачей агенту

Перед тем как отдавать новую задачу агенту, проверьте:

### [ ] A. Понятен ли один конкретный результат?
Если результат нельзя назвать одним предложением, задача слишком широкая.

### [ ] B. Есть ли явные ограничения?
Если агенту не сказано, что запрещено предполагать или менять, он начнёт достраивать контекст сам.

### [ ] C. Есть ли способ проверить результат?
Если проверки нет, вы получите правдоподобный, но ненадёжный output.

### [ ] D. Понятна ли граница ответственности?
Если не ясно, относится ли задача к [`Core`](README.md:86), [`UI Layer`](README.md:95) или документации, агент может смешать слои.

### [ ] E. Подходит ли размер задачи для одной итерации?
Если задача требует архитектуры, реализации, тестов и UI сразу — скорее всего, её надо делить.

## Главная мысль этого плана

Агентская разработка начинается не с просьбы «напиши код», а с подготовки репозитория к тому, чтобы код можно было порождать маленькими, проверяемыми и осмысленными шагами.

Ваш ориентир:
- меньше расплывчатости;
- больше явных границ;
- меньше больших задач;
- больше проверяемых артефактов.
